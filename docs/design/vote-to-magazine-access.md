# 投票後に「民謡ABC 26曲解説」のWeb雑誌を読めるようにする設計

## 目的

LINEミニアプリで民謡ABCの投票を完了した読者に、26曲それぞれの解説を収録した「本のようなWebページ」の入口を開放する。PDFをダウンロードさせることが主目的ではなく、ブラウザー上で目次から曲を選び、各曲の解説を読んでいくデジタル雑誌体験にする。

## 初期仕様

- 読者はLINEミニアプリを開き、LINE認証を行う。
- 認証済み読者が候補曲から最大5曲を選び、投票を送信する。
- サーバー側でLINE認証と投票内容を検証し、投票記録をD1に保存する。
- 投票が正常に確定したら、そのLINE利用者に「民謡ABC 26曲解説」Web雑誌の閲覧権限（entitlement）を付与する。
- 画面に「投票完了。26曲の解説を読む」導線を表示し、Web雑誌の入口ページへ移動できるようにする。
- 投票後に再訪した場合も、サーバー側で閲覧権限を確認してWeb雑誌を開ける。
- 閲覧権限はブラウザー内のフラグだけで決めない。API側で毎回、または短命な閲覧セッション発行時に確認する。
- 初期案では、一度投票して解放されたWeb雑誌は投票期間後も読めるものとする。後から号ごとの公開範囲や閲覧期間を設定できるデータ構造にする。

## Web雑誌の体験

- 入口ページは表紙・タイトル・説明・「読む」導線で構成する。
- 本文は全26曲の解説を収録し、目次から各曲へ移動できる。
- 各曲ページは曲名、地域、由来・背景、解説、参考資料などを本の見開きのように読みやすく配置する。
- スマートフォンで読みやすい縦スクロールを基本にし、目次へ戻る・前後の曲へ移動する導線を設ける。
- まだ投票していない人には表紙と紹介、投票への導線を表示し、本文は見せない。
- 投票完了後は閲覧権限を確認して入口を開き、再訪時も同じURLから権限に応じた表示にする。
- 26曲の本文データは曲ごとに管理し、Webページ側で共通テンプレートに流し込める構成を目指す。

## ユーザーフロー

1. LINEミニアプリを開く
2. LINE認証
3. 曲を選ぶ（最大5曲）
4. 投票内容を確認して送信
5. サーバーが認証・入力を検証し、投票と閲覧権限を記録
6. 「投票完了。雑誌を読む」を表示
7. Web雑誌の入口から目次を開き、26曲の解説を読む
8. 次回訪問時は認証後、解放済みのWeb雑誌を入口ページから再び開く

## API案

| Method | Path | 用途 |
|---|---|---|
| POST | `/api/votes` | 投票を確定し、対象号の閲覧権限を付与 |
| GET | `/api/me/entitlements` | ログイン中の読者が読める号の一覧 |
| GET | `/api/magazines/{issueId}` | Web雑誌の表紙・目次などのメタデータを取得。権限を確認 |
| POST | `/api/magazines/{issueId}/reading-session` | 権限確認後、短時間有効な閲覧セッションを発行 |

エンドポイント名は実装前の案。26曲の本文はWebページ用の構造化データとして管理し、本文APIまたはサーバー側レンダリングで配信する。公開URLに本文データをそのまま置くだけではURLを知る人が読めるため、アクセス制御した配信方法を選ぶ。

## データモデル案

- `votes`: 投票ID、LINE利用者の内部識別子、選択曲ID、作成日時、冪等性キー
- `entitlements`: 内部利用者ID、対象号ID、付与理由（`vote`）、付与日時、状態
- `magazine_issues`: 号ID、タイトル、公開状態、閲覧ポリシー、コンテンツ参照先
- `magazine_articles`: 号ID、曲ID、表示順、見出し、解説本文、参考資料。26曲を共通テンプレートで表示する
- `reading_sessions`（必要に応じて）: セッションID、対象号ID、有効期限。長期の認証秘密をブラウザーに保存しない

同じ利用者が同じ対象号の閲覧権限を重複取得しても、権限レコードは一意になるようにする。投票が再送された場合に二重投票・二重権限付与が起きないよう、トランザクションと冪等性を考慮する。

## セキュリティ・運用

- LINE IDトークン等はWorkers側で検証し、クライアントから送られたプロフィール文字列を本人確認に使わない。
- 閲覧権限の判定はサーバー側で行い、フロントエンドの表示切替だけに依存しない。
- コンテンツは公開バケットにそのまま置かない。Workersによる権限確認後の配信、または期限付き署名URLなどを検討する。
- 雑誌本文・画像・PDFの転載を完全には防げないことを明示する。画面表示の保護だけをDRM相当と見なさない。
- 読者のLINE識別子を公開データや公開JSONLに含めない。
- 管理者による無料閲覧権限の付与・取り消し、号の公開停止、障害時の対応手順を設ける。

## 受け入れ条件

- [ ] LINE認証済みユーザーが投票できる。
- [ ] 有効な投票の確定と閲覧権限の付与が整合している。
- [ ] 投票APIの再送で二重の投票・権限が発生しない。
- [ ] 投票完了画面から「26曲の解説を読む」を押してWeb雑誌を開ける。
- [ ] Web雑誌に表紙・目次・26曲の解説ページがある。
- [ ] スマートフォンで目次・曲間移動・目次への復帰ができる。
- [ ] 権限のないユーザーは雑誌本文を取得できない。
- [ ] 認証済みユーザーが再訪した際、解放済みの号を再び開ける。
- [ ] 閲覧権限・投票記録に関するテストを用意する。
- [ ] コンテンツ配信先が公開URL経由で迂回できないことを検証する。
